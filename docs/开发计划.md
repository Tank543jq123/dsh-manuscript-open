## 批次 1 · 入册口与检索（4 个 P0）

### Step 1 · `commit` 拒绝无效条目，修空 id 文件名

| 项 | 内容 |
|:---|:---|
| **目标** | 入册口不再接受"半个对象"；中文 id/标题不再退化成 `.json` |
| **文件** | `lib/commit.js` |
| **函数** | `uniqueId()`、`commitEntries()` |
| **方案** | ① `uniqueId()` 的空基名改为兜底 `e-unknown`（现在空串会写出 `entries/.json`）；② `commitEntries()` 入口加最小校验：缺 `title` / `claim` / `volume` 任一项，或清洗后 id 为空 → 该条 `skipped += 1` 并回传原因，不写盘；③ `ids` 只回传真正写成功的 id |
| **影响面** | 只影响 `POST /api/distill/commit` 与 `manual_distill` 的入册结果；`buildLibrary` 走另一条路径不受影响；已有 33 项 `test-commit` 需保持全绿 |
| **验证** | ① 现有 `test-commit.mjs` 33 项全绿；② 新增 3 条用例：缺字段被拒、纯中文 id 不产生 `.json`、正常条目照旧写入；③ 复跑诊断脚本确认 `ids:[""]` 消失 |
| **风险与回滚** | 风险：误判"合法但缺 volume"的条目被拒（现有 `ensureVolume` 会自动归收件箱）。取舍——`volume` 缺失本就不该由入册口猜，拒绝并报原因更诚实；如需保留自动归箱，只校验 `title`/`claim`。回滚：单文件单提交，`git revert` 即可 |

### Step 2 · `commit` 幂等：同一条内容不重复入册

| 项 | 内容 |
|:---|:---|
| **目标** | 双击"入册"或请求重试，只产生一条条目 |
| **文件** | `lib/commit.js` |
| **函数** | `commitEntries()` |
| **方案** | 按**内容指纹**判重（`title + volume + chapter + claim` 的 sha256 前 12 位），而不只按 id：指纹已在库里 → `skipped += 1`，回传 `{ids, skipped, reasons}`。同时把 `uniqueId` 的"-2 后缀"限制为**仅当 id 相同但内容不同**时才用（真冲突才改名） |
| **影响面** | 入册语义从"尽力写入"变成"幂等写入"；`adjudicate` 的重复检测仍在更早一层，二者互补；`test-commit` 会增加用例 |
| **验证** | ① 同一条提交两次 → 第二次 `written:0 skipped:1`；② 内容不同的两条（同 id）→ 仍按后缀避让写入；③ 全库重建后 `created=0 kept=N` 不变 |
| **风险与回滚** | 风险：内容几乎相同但有细微差别的条目被判重（如仅时间不同）。取舍——指纹不含 `provenance`/时间，只含结论字段，避免"时间一改就绕过判重"。回滚：单提交 revert |

### Step 3 · 中文短查询可达（检索与 L2 一起恢复）

| 项 | 内容 |
|:---|:---|
| **目标** | 2–3 字的中文查询能命中；同时保持"查不到就说没有"（不误召回） |
| **文件** | `lib/index.js` |
| **函数** | `matchEntries()`、`buildPrefetchDecision()` |
| **方案** | 把写死的"cjkHits ≥3"改成按查询长度分档（实施后定稿）：<br>① 短查询（≤3 个有效 bigram，即 2–4 字）—— 命中标题里任一 bigram 即入选；<br>② 长查询 —— 需命中 ≥2 个不同 bigram；<br>③ 英文词 / 强数字独立成立。<br>标题命中记 2 分、只命中 claim 记 1 分。L2 整句查不到时按虚词切段重试（只取纯中文且 ≥2 字的段，避免代码片段噪声）。 |
| **影响面** | 只影响检索排序与 L2 预取命中率；`manual_recall` 返回条数不变（8 条）；`test-recall-filter` / `test-apply-section` 的召回断言会需要同步更新（属预期变化，不是回归） |
| **验证** | ① 6 个中文短查询（电源/排针/嘉立创/选型/测试/插件）命中数从 0 → ≥1，且 top1 标题确实含该词；② 对抗样本「完全不可能命中的词串xyzzy」「zzz绝不可能命中的查询qqq」仍为 0；③ L2 三个真实首句至少 1 个命中；④ `selfcheck.mjs` 的 fail-closed 断言保持通过 |
| **风险与回滚** | 风险：放宽后被高频虚词带偏，召回变噪声。用"覆盖度 + 停用表 + 对抗样本回归"三重约束；一旦对抗样本回归失败，立刻回到旧阈值。回滚：单提交 revert |

### Step 4 · 让"能不能修好"可被别人验证

| 项 | 内容 |
|:---|:---|
| **目标** | 换台机器也能判断这套东西是否达标，而不是只有作者那台能跑 |
| **文件** | `scripts/selfcheck.mjs`、`scripts/test-apply-section.mjs` |
| **函数** | 阈值断言处、`process.argv[1]` 伪造处 |
| **方案** | ① `selfcheck` 的样本量断言参数化：`>=200` 改成 `>=1` 并**标记为跳过**（样本不足时不判红，只输出事实），事件数/无版本号同理；② `test-apply-section` 不再硬编码 Windows 路径，改为从 `import.meta.resolve('@deepseek-ai/dsh')` 或环境变量 `DSH_BIN` 解析，解析不到时**跳过着色断言并明确打印"跳过原因"**，不制造假红 |
| **影响面** | 只动测试脚本，不动产品代码；Windows 下的行为不变 |
| **验证** | ① Linux 上 `selfcheck` 不再 fatal，输出"N 项通过 / M 项跳过"；② `test-apply-section` 在本机 11/11 全绿（当前 7/11）；③ Windows 侧行为未变（无 CI 时由人工确认） |
| **风险与回滚** | 风险：把断言放宽成"永远绿"，失去回归价值。约束——**阈值只允许"跳过并打印"，不允许静默通过**；关键项（幂等、fail-closed、损失口径）仍是硬断言。回滚：单提交 revert |
