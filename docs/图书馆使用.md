# 图书馆（Markdown 藏书）使用说明

> 2026-11-12 起，书阁的「藏书」不再是一堆只有程序认识的 JSON，而是**一个你自己指定的目录，里面一条经验一个 `.md` 文件**。
> 多个 DSH 实例（web、superagent、甚至别人机器上的实例）只要指向同一个目录，就能共享同一份藏书。

## 1. 配置路径

优先级从高到低：

| 顺序 | 方式 | 说明 |
|---|---|---|
| 1 | 环境变量 `DSH_MANUSCRIPT_ROOT=/abs/path` | 硬覆盖，测试/CI 用；面板改不动它 |
| 2 | 配置文件 `~/.dsh/dsh-manuscript-config.json` 的 `root` | 推荐。面板「图书馆」里也能直接改 |
| 3 | 默认 `~/.dsh/dsh-manuscript` | 没配置时用这个 |

当前这台机器的配置：

```json
{ "root": "~/.dsh/library" }
```

改完不需要重启：面板保存后下一次扫描即生效（也可点面板的「重新扫描」，或 `POST /dsh-manuscript/api/rescan`）。

## 2. 目录长什么样

```
~/.dsh/library/
├── vol-03/                     # 一册一个目录（vol-01 … vol-08）
│   └── ch-plugin/              # 一章一个目录
│       └── e-xxxx.md           # 一条经验一个文件
├── VOL.01 硬件设计与器件选型/  # 你自己建的目录也认（任意名字）
│   └── 继电器选型.md
├── library.json                # 派生索引（程序重建，不用手改）
├── legacy-json/                # 迁移前的旧 JSON，只读保留
└── .state/、runs/、snapshots/  # 运行态，不要往里放东西
```

## 3. 直接扔文档进来

**任何 `.md` 文件放进去就会被收编**，可以没有 front-matter：

- 标题 = 文件名（去掉 `.md`）
- 摘要（claim）= 正文第一段（去掉 `#` 标题行）
- 正文（why）= 其余段落
- id = `md-` + 文件路径哈希（稳定，重扫不会产生重复条目）

想被更好检索，可以加 front-matter（可只写其中几项）：

```markdown
---
title: 继电器直流感性负载要加续流二极管
claim: 不加续流二极管，触点半年左右就粘连。
tags: [硬件, 继电器]
---
正文……
```

程序自己写出的条目会带完整 front-matter（`id`/`volume`/`chapter`/`confidence`/`authority`/`provenance` 等），同样可以直接改。

## 4. 备份与迁移

- 备份 = 直接复制整个目录（`cp -a ~/.dsh/library ~/backup-library`）
- 换机器/换实例 = 把目录放过去，然后指到同一个路径
- 从旧 JSON 迁移：`node scripts/migrate-json-to-md.mjs --from <旧库> --to <新库>`（会做往返校验，旧数据保留在 `legacy-json/`）

## 5. 已知边界

- 手改 `front-matter` 里的 `claim`/`why` 生效；手改**正文**目前只是人读副本（要看正文结论请改 front-matter）。
- 目录扫描不跟随目录符号链接；`runs/`、`snapshots/`、`archive/`、`models/`、`legacy-json/` 不会被当成藏书。
- 同名文件不会互相覆盖（id 由路径哈希决定）。
