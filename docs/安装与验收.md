# 安装与验收清单

> 给"我想自己跑一遍看看"的人。全程约 5 分钟，**不需要改代码**。
> 前置：Node ≥ 22.19（`node -v` 自查），DSH ≥ 0.2.1-alpha.4 且 < 0.3.0。

---

## 一、装

```bash
# 1) 把包链进 profile（<profile> 换成你自己的，如 web / default）
cd ~/.dsh/profiles/<profile>
pnpm add file:/path/to/dsh-manuscript

# 2) 让 profile 引用它（package.json 里加一行）
#    "dsh": { "profile": { "bundles": [ ... , "dsh-manuscript" ] } }

# 3) 重启 DSH（不是刷新页面）
```

装完应该看到：

- 左栏底部一张常驻迷你卡：`📖 书阁  N/M ▓▓▓░░ 归档 N`
- 左栏图标行多一个书本图标（折叠成 56px rail 时是一个进度环）
- 点它 → 打开「书房」主面板

> ⚠️ **这台机器的 UI 从未被真实渲染验证过**（开发期只做了静态加载测试）。
> 所以这一步如果发现布局问题，是**预期内的**——记下来发我，比修 bug 更有价值。

## 二、不用重启就能做的验收（推荐先跑这三条）

```bash
cd /path/to/dsh-manuscript

# ① 常驻目录长什么样、有没有超预算
node scripts/verify-prefetch.mjs --catalog

# ② 检索与首轮预取是否正常（3 句该命中 + 2 句必须 0 命中）
node scripts/verify-prefetch.mjs --suite

# ③ 全量自检（23 项；会写库，但写的是你指定的根）
node scripts/selfcheck.mjs
```

预期：第 ② 条 5/5 符合预期。若"该命中的 0 命中"，通常是**这个库里确实没记过**
（换一句你确定记过的），或 `DSH_SESSIONS_ROOT` 指错了。

## 三、真实验收：「先翻阅」到底成不成（S2）

这是唯一"没有它就等于没做成"的判据，必须在一个真实会话里验：

1. 新开一个会话（换一个 `agent`，避免命中已预取过的 agent）
2. 问一个**手册里确实记过**的事，例如：
   > 上次那个插件是怎么装的？
3. 看 Agent 的第一句：
   - ✅ 成功：「我看到手册里记过……」→ 并且会用 `manual_read` 读正文
   - ⚠️ 半个成功：直接回答了，没提手册 → L1 目录没生效或它没用工具
   - ❌ 失败：说「手册无记录」→ 用第 ② 条同一句跑 `verify-prefetch`，看是不是检索问题
4. 再问一个明显没记过的事：
   > 完全不可能命中的词串 xyzzy
   - ✅ 正确：「手册无记录」
   - ❌ 失败：它编了一个答案 → fail-closed 破了，这是红线级别的问题

## 四、入册走一遍（验证写链路）

1. 面板 → 提炼 → 预演（`dryRun`，不花钱）看会提炼哪些会话
2. 真跑一小批（`limit=1`）
3. 点「入册」，然后看：
   - `/api/summary` 的 `entries` 是否 +1
   - 对应册的 `MANUAL.md` 里是否多了一条（含「证据：」行）

## 五、常见现象对照表

| 现象 | 多半是 |
|:---|:---|
| 左栏没有书阁卡 | 没重启宿主（浏览器刷新不够） |
| 面板打开是空白 | 服务端还在扫描（首次全量约 2 s / 300 会话约 20 s），等一会儿 |
| `/api/summary` 503 | 首次扫描未完成（503 里只有 error）。等它就绪后再 `curl`，看 `scanErrors` 计数与 `scanErrorsSample` 前 10 条明细 |
| 数字比磁盘少 | 内存快照有 10 分钟 TTL；看响应里的 `stale` / `scanAgeMs` |
| 想重扫但界面没有按钮 | **面板目前没有重扫入口**（只有 HTTP 端点）。手动触发：`curl -X POST -H 'x-dsh-manuscript: 1' http://127.0.0.1:<端口>/dsh-manuscript/api/rescan`，看响应里的 `scanSeq` 有没有前进；没前进 = 被建库锁跳过（409） |
| 问手册里的事却说"无记录" | 先用 `verify-prefetch` 复现，确认是检索问题还是内容真没有 |
| 担心书库不健康 | **面板目前不展示 health**（数据有、UI 没消费）。`curl` `/api/summary` 看 `health.issues` 与 `invalidEntries`；多为上次建库崩溃残留的 `.staging-*`（>1 小时会被自动清理） |

## 六、回滚

```bash
# 从 profile 的 package.json 里删掉 "dsh-manuscript" 那一行，然后重启 DSH
```

插件**从不删除**书库内容；卸载后 `~/.dsh/dsh-manuscript/` 原样保留，
重新装回来即可继续用（`entries/` 是真相层）。
